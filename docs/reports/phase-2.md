## ผล oracle (ข้อ 4)

ไฟล์ `src/domain/split.oracle.test.ts` คำนวณค่าจริงด้วยเศษส่วน BigInt โดยไม่ใช้ helper ของ domain บิลสุ่ม 2,000 ใบผ่านทั้งหมด

**เกณฑ์ `items + 4` สตางค์ไม่จริงทุกกรณี** ทั้งที่โค้ดคำนวณตาม spec:

| กรณี (บวก VAT, เศษ 1 สตางค์ต่อรายการตกที่คนเดิม) | คลาดจริง | `items + 4` |
|---|---|---|
| 8 รายการ หาร 6 คน service 100% | 14.15 | 12 |
| 40 รายการ หาร 20 คน service 10% | 44.65 | 44 |

เกณฑ์ที่ใช้แทนคือ `ceil(v × (1+s) × (n+1)) + 4` สตางค์ (n = จำนวนรายการ, s = อัตรา service, v = 1.07 ถ้าบวก VAT ไม่งั้น 1) ที่มาของสูตรเขียนไว้ในคอมเมนต์ของไฟล์เทสต์ ขอบเขตที่พิสูจน์ได้คือน้อยกว่า `v(1+s)(n+1) + 3.105` (แผนเดิมใช้ `floor` ซึ่งพิสูจน์ได้ไม่ครบ จึงเปลี่ยนเป็น `ceil`) ทั้งสองกรณีในตารางเป็นเทสต์ถาวร

ตรวจว่าเกณฑ์จับของผิดได้จริง: แก้โค้ดชั่วคราวให้หารส่วนลดเท่ากันแทนตามสัดส่วน แล้ว property นี้ล้ม

เกณฑ์นี้หลวมกว่าของรีวิว จึงจับความคลาดระดับไม่กี่สตางค์ไม่ได้

## การจัดการข้อมูลเสีย

**พฤติกรรม**
- ตรวจตอนโหลด: Σ`payers` = Σ`owed`, วันที่มีจริงรูปแบบ `YYYY-MM-DD`, ยอดอยู่ในช่วง โดย**ไม่คำนวณ `owed` ใหม่**
- รายการเสียถูกกักพร้อมข้อความภาษาไทย รายการอื่นโหลดตามปกติ และ**ข้อมูลดิบถูกเก็บต่อแม้มีการบันทึกครั้งถัดไป**
- อ่านทั้งก้อนไม่ได้ หรือมาจากแอปเวอร์ชันใหม่กว่า: ไม่เขียนทับเด็ดขาด
- ก่อนเขียนตรวจด้วย schema เดียวกับตอนโหลด ถ้าเขียนไม่สำเร็จจะแจ้งกลับและข้อมูลเดิมไม่เปลี่ยน
- record ของ "ฉัน" ใช้ id `me` เสมอ ถ้าเสียจะสร้างใหม่ด้วย id เดิม รายการต่างๆ จึงยังเชื่อมกัน

**ข้อจำกัด:** ข้อความไทยมีให้แล้ว (`describeQuarantined`) แต่**ยังไม่มีหน้าจอแสดง**

**เทสต์หลัก** (`src/storage/parse.test.ts`)
- `a corrupted bill > with payers and owed differ is set aside with a Thai message, and the rest loads` และแบบเดียวกันอีก 7 กรณี: วันที่ไม่มีจริง, วันที่ผิดรูปแบบ, ยอดติดลบ, เศษสตางค์, เกินเพดาน, เงินเป็นข้อความ, field หาย
- `a corrupted bill > that repeats an id is set aside, keeping the first`
- `a corrupted bill > does not have its owed amounts recalculated`
- `other damaged records > recreates my record under the same id if it is damaged`
- `parse properties > never throws on arbitrary JSON`
- `parse properties > survives any single damaged field, and what loads is safe to use`
- `parse properties > loads everything the app can create, with nothing set aside`

**เทสต์หลัก** (`src/storage/repository.test.ts`)
- `quarantined records > keep their raw data through later saves`
- `a store that cannot be used > that is not JSON is never overwritten` (และกรณีรูปแบบผิด / เวอร์ชันใหม่กว่า)
- `saveBill > ignores an owed passed in by the caller`
- `saveBill > never saves a bill that loading would set aside`
- `saveBill > reports a full storage and leaves the old data alone`

## ฟอนต์

- **Mitr ไม่รองรับ `tabular-nums`:** ความกว้างตัวเลขที่น้ำหนัก 500 อยู่ระหว่าง 488 ถึง 741 หน่วย ยืนยันทั้งจากเบราว์เซอร์และไฟล์ฟอนต์
- **ตัวอักษรคล้ายกัน:** ใน Mitr บ กับ ป แยกง่าย ส่วน ก ถ ภ และ ข ช ต่างกันน้อย
- **Rubik ไม่มีตัวอักษรไทย** จึงใช้ทั้งแอปไม่ได้
- **ที่เลือก (เจ้าของยืนยันแล้ว): Mitr ใช้กับข้อความทั้งหมด และ Noto Sans Thai ใช้กับยอดเงิน** ตัวเลข 0–9 ของ Noto Sans Thai กว้าง 572 หน่วยเท่ากันทุกตัว (น้ำหนัก 400 และ 500) จึงเรียงตรงคอลัมน์ได้ ข้อนี้อ่านจากไฟล์ฟอนต์ **ยังไม่ได้ดูภาพของคู่นี้ตามการแบ่งหน้าที่ข้างต้น**
- Noto Sans Thai ไม่ใช่ฟอนต์ตัวมน ขณะที่ spec เดิมขอฟอนต์ตัวมนสำหรับตัวเลข
- ถ้า Mitr ใช้กับชื่อคน ปัญหาตัวอักษรคล้ายกันยังอยู่ ผู้พัฒนาเสนอให้แสดงชื่อไม่ต่ำกว่า 16px (ยังไม่ได้ตัดสิน)
- `line-height` 1.2 ตัดสระ/วรรณยุกต์ของ Mitr ส่วน 1.5 พอดี
- ยังไม่ได้ตรวจบนมือถือจริง
